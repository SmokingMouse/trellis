# ADR：设置与功能排布重组 —— 按「持久对象 / 当下语境 / UI 偏好」三分

- **日期**: 2026-07-31（Session 89）
- **状态**: 方案已定，未实施
- **完整实施计划**: [`console-ia-spec.md`](../console-ia-spec.md)（六批改动 + 判据 + 风险）
- **修订**: `decisions.md` 的 **2026-07-29「设置页承载点一下更新」** 条目（其中"偏好类不搬进来"
  一半保留、一半被修订，见下文「被修订的旧决策」）；实现 `custom-agents-plan.md:304` 那条没做的建议

## 背景

S88 把自定义 Agent 层和自动化任务一次做完之后，产品表面出现了 S88 之前没有的一类东西：
**持久对象**——有 CRUD、跨 session 存活、被 id 引用。

Trellis 原来的组织原则写在 `app/settings/page.tsx:5-8`：**刻意不做偏好中心，一切配置都语境化**；
`/settings` 存在的唯一理由是"更新没有语境化的家"。这条原则对**当下语境**（mode / workspace /
model，创建时锁定）和 **UI 偏好**（主题 / 发送键 / 宽度）都成立，但对持久对象结构上不成立——
agent 和 task 没有"当下"可挂。

于是它们各被甩成一张整页，并且**不对等**：task 拿到了 Header 位（`Header.tsx:374-385`），
agent 停在 `/settings/agents` 需要走两跳；两页互链缺一条边；三张整页各自手写了一套
「运行配置」表单，其中任务页的 workspace 退化成裸绝对路径 input（`app/tasks/page.tsx:262`），
根本不接 `workspaces` 表。同时两张表各有一批字段只能由 API 改
（`agents.permission` / `require_approval`、`tasks.timeoutMs` / `overlapPolicy` / `maxBudgetUsd`）。

**这不是"没排整齐"，是一条原则被新对象撑破后没有补上新原则。**

## 决策

### 1. 把配置按「谁拥有它、活多久」三分，而不是按"是不是设置"

| 类别 | 判据 | 归宿 |
|---|---|---|
| 持久对象 | 有 CRUD、跨 session、被 id 引用 | 一个管理台（`/settings` 左 tab 壳） |
| 当下语境 | per-session / per-message，创建时锁定 | 留在原地，但用同一个组件 |
| UI 偏好 | per-browser，随时可改，无副作用 | 原地控件不动 + 管理台加可穷举镜像 |

**Why**：这三类的**修改时机**根本不同——持久对象是"我现在要去配一个东西"（目的性访问，
需要可穷举的列表），当下语境是"我正要开始做这件事"（顺手，必须在手边），UI 偏好是
"这个太窄了"（就地触发）。按这条分，每一类该放哪是推导出来的，不是拍的。

**Alternatives**：
- 按"是不是设置"分（把所有能配的都塞进 /settings）—— 拒绝，这正是 2026-07-29 那条已经
  论证过的错误，语境化的东西搬走只是多一跳。
- 维持现状只补链接 —— 拒绝，链接补了但三份手写表单还在漂，且下一个持久对象
  （飞书群绑定、多 agent 讨论组，ADR `2026-07-31-custom-agents.md` 明确说了要长在同一层）
  又会随手甩出第四张整页。**这条原则的价值主要在下一次，不在这一次。**

### 2. 「运行产物」是第四类，不属于设置，回主 SPA

任务的每次执行不是配置，是工作面。而它的落点**本来就是** session/node
（`lib/server/tasks.ts:374-376` 打 `kind='task'`，`lib/server/repo.ts:342-352` 从侧栏滤掉）。

决策：**侧栏底部开一个「⚙️ 自动化」折叠组**（照 `🗄 已归档` 的实现），每行一个任务，
点进去是主 SPA 正常渲染。`/settings/tasks` 只剩定义 CRUD。

**Why**：`/tasks` 页现在把「列表 + 运行历史 + 深链」在 SPA 外重实现了一遍，而 SPA 里
早就有工具卡片、就地分叉追问、全文搜索、TaskToast。ADR `2026-07-31-custom-agents.md` 决策 7
当初选择"任务执行落在 session/nodes 上不另造渲染"，正是为了拿到这些——**但把落点藏起来
等于把红利放弃了一半**。这一批是在兑现 S88 已经付过的成本。

`repo.ts:347` 隐藏它的理由（"一个每日任务一个月能产 30 个节点"）经复核**只对节点数成立，
对侧栏行数不成立**——行数 = 任务数。真正的未知在多根会话的渲染表现，列为前置调研（spec R1）。

**Alternatives**：
- 保持隐藏，只在 `/settings/tasks` 里看 —— 拒绝，等于长期维护两套渲染。
- 每次运行建一个新 session —— 拒绝，S88 已经论证过（`custom-agents-plan.md`），
  会把侧栏彻底淹掉，且丢掉"同一个任务的历次运行在一起"。

### 3. 管理台不是"设置页加 tab"，而是持久对象的**库**

六个 tab：Agent / 自动化任务 / 模型与 Provider / 工作区与 CLI / 偏好 / 版本与更新。
其中「模型与 Provider」是把埋在 `ModelPicker.tsx:119` 下拉底部的 `ModelConfigModal` 抬出来，
「工作区与 CLI」是把藏在 `SessionSidebar.tsx:589` 一个长 title 小按钮里的 CLI attach 抬出来。

**Why**：判断一个东西该不该进管理台，用的是决策 1 的判据，不是"看起来像不像设置"。
ModelConfigModal 编辑的是 `~/.config/sm/endpoints.yaml`（**跨应用共享**）——按判据它是最典型的
持久对象，却只有一个下拉底部的入口。

**顺带得到的**：左 tab 壳天然补齐三页互链的缺边，且下一个持久对象加 tab 而不是加整页 + 加 Header 图标。

### 4. Header 收敛到一个 ⚙，但**必须等批 4 落地才删 ⏱**

**Why**：删 ⏱ 的前提是任务的日常入口转移到侧栏。批 1 单独发布时如果先删，中间态是纯粹的退步
（任务从 1 跳变 2 跳且没有替代入口）。这条写进 spec 的风险 R3，因为它是最容易在实施时抄近路搞错的一步。

### 5. 偏好做**镜像**不做搬家

抽 `lib/prefs.ts` 集中 ~25 个 localStorage key，管理台「偏好」tab 渲染一份可穷举清单，
**与原地控件共用同一个 store**。原地的 popover / 输入框脚注一个都不动。

**Why**：2026-07-29 那条的理由是"搬进来只是多一跳"——**这条只否定搬家，没否定镜像**。
今天的真实代价不是多一跳，是**数不清**：25 个 key 散在 8 个文件，`trellis-theme` 还在
`hooks/useTheme.ts:17` 和 `app/layout.tsx:33` 双份硬编码。"我知道有这个设置但找不到在哪改"
是镜像清单要解决的，与语境化不冲突。

### 6. 抽一个共用的 RunConfig 组件，文案单一真源

agent / workspace / contextMode / model / approval 五个字段，三种 variant（新会话 / 任务定义 /
agent 定义）。文案抽 `lib/run-config-copy.ts`，照 `lib/agent-presets.ts` 已经证明过的先例
（S88 把内置人设文案抽成 schema 与 UI 的唯一真相源）。

**Why**：这是本方案里唯一**治病而非治症**的一批。任务页的裸路径 input、另手写的 contextMode
文案、第三份 agent 下拉，都不是各自的疏忽，是"没有共用组件"这一个原因的三个表现。
不抽的话，下一个引用 agent 的东西（讨论组）会写第四份。

## 被修订的旧决策

**`decisions.md` 2026-07-29 · 「偏好类（主题/发送键/宽度）仍不搬进来，那条理由至今成立」**

- **保留的一半**：不搬家。语境化入口仍是主路径，原地控件一个不动。
- **被修订的一半**：当时的论证是"偏好少且各有语境化入口"。**"少"这个前提已经不成立**——
  从 S62 评估时的几个涨到今天的 ~25 个，且散在 8 个文件里。新增镜像清单不推翻语境化，
  是补上"可穷举"这个当时不需要的性质。

**`app/settings/page.tsx:5-8` 的文件头注释**在实施时需要一并改写——它现在描述的是一个
不再成立的取舍。

## 后果

- **Header 少一个图标、侧栏多一个折叠组**。侧栏是 Trellis 唯一的"推挤式"布局
  （发布 `--trellis-sb`，Tabs / Canvas / DockedComposer / 终端全部读它），加折叠组不改宽度，
  但要复核已归档组在同屏时的堆叠。
- **批 6.1（`tasks.model` 实际存 providerId）是本仓库第一次做减法 DDL**。
  `decisions.md` 2026-07-28 把"`migrate()` 全是加法 DDL"列为部署方案可行的理由之一，
  这条要保住：加列 + 双写 + 读时兜底，旧列留一个版本再删。
- **验收用行为指标不用完成度**。照 S1 workspace 那次的教训（做完了但 `created_by='trellis'`
  实测 0 行、上线三天一次都没被成功用过）：判据是"上线一周内从侧栏进入任务会话的次数 > 0"，
  不是"侧栏组做出来了"。
- **本轮不碰执行链**。`applyAgent()` 的边界（`2026-07-31-custom-agents.md` 决策 5：
  只改人设 + 能力面，绝不碰上下文与身份）全程不动——它撑着 chat B-fork 和 project
  per-lineage isolation 两套本来就脆的机制。
