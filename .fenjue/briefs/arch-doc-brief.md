## 5. 硬约束

- 篇幅 3000–5000 字（CJK 字数）。
- 飞书阅读形态（`write-tech-design/references/feishu-engineering-doc.md` 全部规则）：标题编号；列表与表格优先，散文只在节首就位段与过渡句；粗体只做路标不整段加粗；服务名/文件名/字段名用粗体或纯文本，行内代码只留真命令与真代码；一级节之间留空行或分割线；每个大节开头 1–2 句「本节读法」。
- 每个组件必须标注「**main 已上线**」或「**分支在途，未上线**」。
- 不写任何凭证、token、env 值；不写带用户名的绝对路径（用仓库相对路径；跨仓库写仓库名 + 相对路径）。
- 没有代码或文档依据的话不写；写不准的标「未核实」。不写「实测」除非引用了带命令输出的报告。
- 图三张，一图一问：
  1. 总览架构图（回答「有哪些部件、谁连谁、哪些在 main 哪些在分支」）：SVG，单独文件 `overview.svg`，画板可编辑；分支在途的部件用虚线框并标注。
  2. 会话执行链路时序图（回答「一条消息从浏览器到 CLI 再回到页面走过谁」）：Mermaid `sequenceDiagram`，遵守飞书 Mermaid 安全子集（不用花括号、标签换行用 `<br/>`、节点标签含括号整体加双引号）。
  3. 迁移三步 Before / After（回答「每一步改了什么、老链路何时拆」）：表格；若做成图则 SVG 单独文件 `migration.svg`。
- 发布平台：飞书文档（后续由另一单转 XML 导入，本单只交 Markdown + 图文件）。

## 7. 骨架（已拍板，不出候选）

1. **先看结论**：四行状态表（线上 / Herdr 桥 / 影子模式 / agent-server：一句话是什么、状态、下一步）+ 总览架构图。
2. **入口清单**：仓库与分支、验证实例与端口、库文件、关键文档路径（表格）。
3. **Trellis 线上架构**：3.1 进程模型（大门 + Next + 终端）；3.2 数据模型（主要表与职责）；3.3 会话执行链路（时序图 + 表）；3.4 transcript 导入；3.5 SSE；3.6 飞书与定时任务；3.7 验证脚本体系与部署形态。
4. **在途线一 · Herdr 桥**：要解决的问题；「会话归出生地、跨界即分叉」原则；组成（socket 客户端、hooks、侧栏嵌套）；当前状态（复核轮次、真机实例）；未决项。
5. **在途线二 · agent-server**：为什么要它（薄前端、多前端同看同一会话）；协议要点表（thread/turn/item、审批请求、seq 与 completedSeq、租约、队列语义）；引擎与传输；TUI；验证到哪一步（Mock → 真引擎实跑）。
6. **在途线三 · 影子模式与三步迁移**：第一步做了什么、复核结论；三步 Before / After 表；现在所处位置。
7. **开放问题与取舍表**：依赖打包（vendor 临时 vs 发包）、鉴权与多租户、审批只读通知缺失（80 KB/s 轮询）、pane 与 AS thread 身份归一、其它复核遗留。
8. **术语表**：Herdr、pane、workspace、worktree、fj / herdr-leader、thread / turn / item、run-bus、cli-sync、影子模式。
