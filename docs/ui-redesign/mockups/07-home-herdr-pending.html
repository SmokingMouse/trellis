冷 Tab 排序根因剖析：为什么看起来像「创建时间」而非「活跃时间」？

深入排查 lib/herdr-console.ts、HerdrFleetPickerSheet.tsx 与底层绑定：

链路环节 现状表现 (Bug 根因) 为何退化为创建时间 修复方案
1. 时间戳来源 只取 view.hook?.updatedAt。无 hook 或纯 shell 的 pane 其 activityAt === null 当 activityAt 为 null 时，比较结果为 0，保持原有数组排序 四级级联回退：Hook 时间 → Transcript mtime (终端输出) → 会话更新时间 → 首次/最后发现时间
2. 初始遍历顺序 buildHerdrConsole 循环遍历 workspace.tabs Herdr 后端按 tab_id (t1, t2, t3...) 返回，正是 Tab 的创建顺序 在视图派生层最后对冷 Tab 数组显式执行 stableSort(byActivityDesc)
3. 空闲窗口比较 cold.sort((a,b) => (b.activityAt ?? 0) - (a.activityAt ?? 0)) 若都为 0，V8 稳定排序直接维持原创建序 保证每个 Tab 均有有效时间戳兜底，绝对不出现 0 - 0 退化
