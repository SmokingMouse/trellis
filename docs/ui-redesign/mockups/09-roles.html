角色 · 交互设计

角色 = 长期存在的 agent：有人设、有自己的记忆、只有一条对话。群聊 = 几个角色加上你在一个房间里。下面是每个交互点的取舍。

交互点做法为什么这样定
入口侧栏导航下面加「角色」分区，排在会话前面；角色和群聊混排，按最近活动排序，最多显示 5 个角色是常驻对象，得一眼看到。和会话列表分开，不然会被几百个会话淹没
一个角色一条对话点角色直接进它唯一的时间线，没有「新会话」按钮；按天分隔Cindy 的核心体验：角色是人，不是会话模板
新话题输入 /new 或点分隔线，插一条「新话题」：从这里起上下文重开，记忆不受影响，上一段还能往回翻长时间线迟早撑爆上下文。CLI 自己 compact 不可控，用户手动切话题更可预期
记忆写入角色每记一条，就在那条回复下面出现紫色小行「记下了 …」，带撤销和改一下记忆最怕偷偷记错。写入当场可见，用户不用去设置页翻
夜间整理每天 03:30 跑；没有新对话就跳过、不调模型。结果是时间线里的一张卡：新增 / 合并 / 删除 / 技能，逐条接受或拒绝复用管家改动卡「先预览、再落库、可撤销」的语义，不另起一套确认流程
一览对话右侧 300px 面板：人设一句话、最近记住的、例行、渠道、后台任务；手机上收进头像对应 Cindy 的 At a glance，不用离开对话就能看清「它是谁、记得什么、在干嘛」
大活角色开后台任务（就是普通会话），时间线里放一张任务卡，完成后回报长任务不该堵住聊天；后台任务在会话列表里照常可见
新建三种起点：空白 / 从模板（现有 6 个预设和管家）/ 从一段会话提炼（读那段对话，生成人设草稿和初始记忆）第三种是 trellis 独有的：你已经有几百个会话，比从零写人设快
群聊发言@ 了谁就只让谁回；没 @ 时默认由路由挑一位回（可改成谁有话谁说，或只有被 @ 的回）默认挑一位最省 token、最不吵；Cindy 默认是 Anyone Can Reply
群聊刹车输入框上方的轮次条：第几遍、多少条、停下这一轮。到上限后给两个出口：继续讨论 / 让管家记成任务角色互相接话容易停不下来。上限照搬 Cindy：3 遍 10 条
群聊落地第一版不做组织者（Organizer）；讨论结果靠 @管家 建成任务两周里 ≥3 次讨论落成任务再做组织者
设置点头像或齿轮进设置页：资料 / 人设 / 记忆 / 能力 / 渠道 / 例行 / 高级；记忆页可搜、可编辑，每条带来源对话链接记忆能追溯到是哪次对话记下的，错了才好改
