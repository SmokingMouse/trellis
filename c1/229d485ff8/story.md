## Prompt

能把压缩渲染的过程展示出来吗

## Summary

为了让**「自动压缩」**在发生时清晰可感知，我们梳理了系统中目前存在的两处核心自动压缩场景及其感知增强方案：

---

### 场景 1：工具动线冷热分段自动折叠（实时执行时）

* **触发时机**：当 Agent 连续执行并完成 ≥3 个普通工具（如连续 3 次 `Read` 或 `Bash`）时，系统自动将它们从多行平铺压缩为单行 **Segment Chip**。
* **目前痛点**：在流式生成中，前几行工具调用会**突然“消失”并合成为一行**，用户容易产生“步骤被吞掉”或“界面跳动”的困惑。
* **感知增强设计**：
  1. **折叠瞬态微动效**：刚被折叠收起的 Chip 触发 1 秒轻微高亮（`bg-accent-muted/40`）与淡入过渡，让视线能捕捉到“它们被收进这个胶囊了”。
  2. **状态感知文案**：Chip 明确带有折叠指示（如 `⋯ 3 步 · 已自动收起 (点击展开)`）。
  3. **Hover 浮层预览**：悬停在 Chip 上即时弹出小 Tooltip，列出折叠的具体步骤，无需点击也能感知内容。

---

### 场景 2：对话上下文自动压缩（Context Compaction / `/compact`）

* **触发时机**：当对话轮次极长、接近上下文窗口上限时，底层 Claude CLI 自动触发 `/compact` 上下文压缩，Tokens 发生断崖式下降。
* **目前痛点**：为了避免把 CLI 注入的压缩摘要误判为普通提问，解析器将其过滤了，但导致**整个界面完全看不到“这里曾经发生过一次上下文自动压缩”**。
* **感知增强设计**：
  1. **时间线/画布分界条**：在发生压缩的两个轮次（Turn）之间，插入一条优雅的 **`🗜️ 上下文已自动压缩`** 分界线（可展开查看压缩摘要与 Token 变化）。
  2. **Header 🧠 状态联动**：当检测到上下文压缩后，顶部 Context 百分比平滑回落，并弹出轻提示（如 *“上下文已自动提炼压缩，腾出空间”*）。

---
